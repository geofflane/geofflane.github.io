Using a core.async Routine as a State Machine

Clojure has a library called core.async that lets you model your system as a set of independent processes that pass messages to each other through channels. Each process is responsible for running itself, managing its own state, and so on. But how do you manage state in a language where everything is immutable?

There are many ways to do that using Atoms, Refs, and Agents. But those constructs are mostly about sharing mutable state between processes, and in many cases end up being more complex than you'd need to implement a state machine that entirely encapsulates its own state transitions. Fortunately there's another way.

A Simple Example

The go block is the basis of each independent process, defining a unit of asynchronous work. It's generally implemented in a loop/recur fashion: a message is received from a channel, processed, and then recur loops back to wait for another. That looping gives the block an opportunity to transform itself into a new state after each message.

;; three states: starting, playing, done
(go-loop
   [state :starting]
   (let [[new-state]
        (case state
              :starting (let [init-value (<! ch)]
                         (some-work init-value)
                         :playing)
              :playing (let [round (<! ch)]
                         (if some-condition
                           :done
                           (do
                             (some-other-work round)
                             state)))
              :done (do
                      (maybe-do-some-cleanup)
                      (close! ch)
                      :done))]
       (if-not (= :done new-state)
          (recur new-state))))

It starts in the :starting state and transforms to :playing when it recurs. The playing state runs over and over until some condition sends it to :done.
